## v3.3.2 - 突破丹背包校验修复 + 灵田一键种植

### Bug：突破丹无需拥有即可强行破境（且永不消耗）
**用户报告**：部分境界（元婴期明显，金丹期不明显）`/突破 <破境丹>` 即使背包没有丹药也会白嫖破境丹加成。

**根因（已确认通用，非分境界）**：
- `handlers/breakthrough_handler.py::handle_breakthrough` 指定丹名时，只校验 `pills_data` 存在 + `subtype=="breakthrough"` + `target_level_index` 匹配，**从不查 `player.get_pills_inventory()`，也从不扣丹**。
- `core/breakthrough_manager.py::execute_breakthrough` 直接把 `breakthrough_bonus` 算进成功率。
- 所谓「金丹期没事」实为当时背包恰好有结丹丹；检查缺失对所有境界生效（已用 9 项断言验证：无丹拒绝 / 有丹扣 1 枚 / 无丹名走基础率 / 修为不足不误扣）。

**修复（两层防御）**：
1. `breakthrough_handler.py`：指定丹名后先查背包，没有则拒绝并提示「可在丹阁购买，或用 /突破 以基础成功率突破」。
2. `breakthrough_manager.py`：突破条件（非最高境界 + 修为足够）满足后，才校验并**扣除**该破境丹；条件不足（如修为不够）不会误扣。死亡分支下玩家被级联删除，丹自然作废。

**⚠️ 设计决策**：破境丹现会**消耗**。原设计文档（sect_elixir_pills.md 2.3）只把破境丹描述为「一次性加成」未提消耗；本次按游戏经济与用户预期补上消耗，关闭「失败也无限白嫖」漏洞。若用户想保留「不消耗」旧行为，撤销这两处即可。

## v3.3.7 - 面板版式重设计 + 双主题（宣纸金默认 / 玄金备选）

### 用户需求（三轮反馈驱动）
1. 「太难看了，这不就是把文字弄个背景吗」⇒ 宣纸+金逐行翻译版被判负。
2. 「排版太难看了，重新做，文字描述不一定要沿用之前的」⇒ 允许重新设计信息架构与文案。

4. 「我觉得第一版的设计好」⇒ **回退到第一版宣纸+金配色**，但保留新版式。

### ⚠️ 关键坑：预览页「无样式」根因
`gen_preview_v336.py` 只把 `render_panel_html()` 的 `<body>…</body>` 内联到预览页，**把面板自带 `<style>`（`_CSS`）整块丢掉** ⇒ 浏览器按裸文字渲染，用户以为电脑坏了。
**教训**：预览渲染函数产物时，必须连 `<style>`/`<head>` 一起带上，或用 **iframe srcdoc** 独立渲染（本次采用后者，与宿主 `html_render` 截图环境一致，且 iframe 天然隔离 CSS，避免预览页 `.sub/.cap` 与面板 `.sub` 类名冲突；高度用 JS 读 `contentDocument.body.scrollHeight` 自适应，srcdoc 与父页同源可读）。

### 实现要点
- **版式重设计（不等同于逐行翻译）**：渲染器先识别面板类型（`_is_player/_is_equip/_is_help`）再从原始文本提取字段重排——
  - player = 游戏角色卡（道号主视觉 → 境界/灵根/职业徽章 → 战力巨字 → 修为/气血进度条 → 属性网格卡 → 随身装备 → 宗门脚注）
  - equip = 装备卡（武器/防具/心法大条目 + 功法胶囊 + 属性加成数值卡）
  - help = 指令手册（金色色块段落标题 + 指令斑马纹）
  - generic = 通用条目式
- **双主题**：`_CSS_THEME_PAPER` / `_CSS_THEME_GOLD` 两套 `:root` CSS 变量 + 共享 `_CSS` 结构 ⇒ **同一套 DOM/类名，仅配色不同**。`render_panel_html(text, theme)`、`THEMES` 字典、`DEFAULT_THEME="paper"`、未知主题回退默认（不抛异常）。配置项 `VALUES.PANEL_THEME`（string，default `paper`），`main.py` 读 `values.get("PANEL_THEME","paper")` 传入。
- **⚠️ 变量化重构的连带修改**：`_frame()` 加 theme 参数、四个 `_render_*(title, sections, theme)` 全部加形参、4 处 `_frame(...)` 调用点传 theme、入口 `render_panel_html` 分发传 theme —— **漏任一处 ⇒ 主题不生效或 TypeError**（模块级常量勿用 `self.`，同理勿漏形参传递）。

## v3.3.7 补丁：修复转图「发糊」+「右侧多余色块」

### 用户反馈
「图片有点糊，另外右边有多余色块」（附线上真实截图）。

### 根因（查 AstrBot + astrbot-t2i-service 源码确认，非猜测）
宿主 `html_render` → `astrbot/core/utils/t2i/network_strategy.py::render_custom_template`，默认 options：
```python
default_options = {"full_page": True, "type": "jpeg", "quality": 40}
```
服务端 `astrbot-t2i-service src/render.py::html2pic`：
- **糊** ⇒ `type=jpeg, quality=40`（JPEG 有损 + 极低质量）。
- **右侧色块** ⇒ 视口默认 **800px**（`_resolve_viewport_size`：显式 viewport_width > HTML meta viewport > 800），而面板 body 只有 490px ⇒ 右侧 310px 空 body 背景。
- 视口优先级链：①`options.viewport_width` ②HTML `<meta name="viewport" content="width=...">` ③默认 800。
- `device_scale_factor_level`：normal=1.0 / high=1.3 / ultra=1.8。

### 修复
- `main.py` 新增模块级 `_render_options()`：`{"type":"png","full_page":True,"viewport_width":PANEL_WIDTH,"device_scale_factor_level":"ultra"}`；`html_render(panel_html, {}, return_url=False, options=_render_options())`。
- `utils/panel_renderer.py` 导出 `PANEL_WIDTH = 490`；`_frame()` 里写入 `<meta name="viewport" content="width=490">` 作**老服务端兜底**（不认 viewport_width 参数时靠 meta 也能消除色块）。
- **`full_page` 必须保持 True**：面板高度不定，截视口会截断底部。视口宽度靠 `viewport_width` 精确指定，两者不冲突。

### ⚠️ 关键工程要点
- **`html_render` 的 `options` 参数是官方支持的**（`star/base.py::html_render(tmpl, data, return_url, options, umo)`）—— 改画质/尺寸不必自己截图。
- **options 键名 = Playwright screenshot API**：`type/quality/full_page/clip/omit_background/scale/viewport_width/viewport_height/device_scale_factor_level/timeout/animations/caret`。服务端 Pydantic v2 默认 `extra="ignore"` ⇒ 老服务端不认新键会**静默忽略**（不 500）。
- **`type=png` 时服务端会 pop 掉 quality**（Playwright 对 png 传 quality 会报错）。
- **`PANEL_WIDTH` 必须与 CSS 里的 `--w` 同步**（两套主题各一处）⇒ 加断言防脱节。

### 验证
- 复刻服务端 `html2pic` 逻辑（本地 Playwright + `channel="chrome"` 免下载 Chromium）做修复前后对比：800×760（模糊+色块）→ **882×1368**（490 CSS px × 1.8 像素比，无色块）。PNG 体积 200-300KB，QQ/微信上限无忧。

## v3.3.8 补丁：商店面板（丹阁/器阁/百宝阁/物品详情）排版重做

### 用户反馈
「商店几个面板的排版都有点乱」。

### 根因
商店面板原先走**通用布局（generic）**，而通用解析器会把商品的三行文本**拆散**：
```
1. [凡品] 培元丹 (破境丹)     → 普通行（商品名孤立）
   价格: 100 灵石 库存:3     → 键值对（价格与库存挤在一行）
   效果: 修为+500             → 键值对（与所属商品脱节）
```
⇒ 一个商品被拆成 3 行散落页面，视觉上"乱"。

### 实现
- **新专用解析器** `_parse_shop_items(text)`：以**商品头行**为锚点（`_SHOP_ITEM_RE` = `^(\d+)\.\s*\[品级\]\s*(名)\s*\((类型)\)\s*(\[折扣\])?$`）重新聚合，后续 `价格:`/`效果:` 行归入当前商品；尾注（下次刷新/提示）单独收进 notes。
- **新布局** `_render_shop()`：2 列商品卡网格 `.shop-grid > .s-item`；卡内 = 序号 + 名称 + 价格(灵石) / 品级徽章 + 类型标签 + 折扣徽章 + 库存 / 效果独立成行（虚线分隔）。
  - **品级 6 档配色**：`RANK_TIER` 12 品级映射 rk0~rk5（凡/珍 → 灵/地 → 天/皇 → 圣/帝 → 道/仙 → 神/混元先天），CSS 变量 `--rk0..--rk5` + `--rk-bg0..5`（两套主题各一份）。
  - **折扣徽章**：`<20%折>` 红框（`s-off`）、`>+20%`（涨价）置灰（`s-off up`）。
  - **库存紧张**（源文本 `库存紧张:N`，stock<=3）→ `s-stock low` 红色高亮。
- **新布局** `_render_item_detail()`：物品详情（`名称: X` 起头）→ 主标题 + 品级/价格徽章 + 描述居中 + 属性条目。
- **路由**：`render_panel_html` 里**先**跑商店解析（通用解析会拆散商品，不能复用），命中则走 shop；否则按原逻辑，最后 `名称:` 开头走 item_detail。
- **`_is_shop` 收紧**（防误伤）：须 (标题在 PAVILION_SUB 或含"阁") **且** 至少一件商品带价格 —— 否则「藏经阁(无价格行)」「丹阁记录」「排行榜」等都会被误判。

### ⚠️ 顺带修掉：转图底部大片空白
- 现象：商店面板（内容 ~810px 设备像素）截图出来 1296px 高，**底部一大片空白**。
- 根因：Playwright `full_page=True` 的截图高度 = **max(内容高, 视口高)**；服务端默认 `viewport_height=720` ⇒ 内容不足 720px 的面板会被补白到 720。
- 修复：`options` 加 `"viewport_height": 10`（极小值）⇒ full_page 按内容实际高度裁剪。实测 丹阁 1296→810、器阁 1296→628，而内容高于视口的「我的信息」1368→1368 **不受影响**。
- **通用解**：任何 `full_page` 截图都应把 viewport_height 压到极小，否则矮内容面板必带空白。
