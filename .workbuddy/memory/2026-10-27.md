## v3.3.2 - 突破丹背包校验修复 + 灵田一键种植

### Bug：突破丹无需拥有即可强行破境（且永不消耗）
**用户报告**：部分境界（元婴期明显，金丹期不明显）`/突破 <破境丹>` 即使背包没有丹药也会白嫖破境丹加成。

**根因（已确认通用，非分境界）**：
- `handlers/breakthrough_handler.py::handle_breakthrough` 指定丹名时，只校验 `pills_data` 存在 + `subtype=="breakthrough"` + `target_level_index` 匹配，**从不查 `player.get_pills_inventory()`，也从不扣丹**。
- `core/breakthrough_manager.py::execute_breakthrough` 直接把 `breakthrough_bonus` 算进成功率。
- 所谓「金丹期没事」实为当时背包恰好有结丹丹；检查缺失对所有境界生效（已用 9 项断言验证：无丹拒绝 / 有丹扣 1 枚 / 无丹名走基础率 / 修为不足不误扣）。

**修复（两层防御）**：
1. `breakthrough_handler.py`：指定丹名后先查背包，没有则拒绝并提示「可在丹阁购买，或用 /突破 以基础成功率突破」。
2. `breakthrough_manager.py`：突破条件（非最高境界 + 修为足够）满足后，才校验并**扣除**该破境丹；条件不足（如修为不够）不会误扣。死亡分支下玩家被级联删除，丹自然作废。

**⚠️ 设计决策**：破境丹现会**消耗**。原设计文档（sect_elixir_pills.md 2.3）只把破境丹描述为「一次性加成」未提消耗；本次按游戏经济与用户预期补上消耗，关闭「失败也无限白嫖」漏洞。若用户想保留「不消耗」旧行为，撤销这两处即可。

### 优化：灵田一键种植
- `managers/spirit_farm_manager.py` 新增 `plant_all(player, herb_name, count=None)`：把全部空种植格一次性种满指定灵草；省略 `count` 填满所有空格，指定数量则只种 N 株（越界只填满剩余）。

- `main.py` 新增指令 **`一键种植 <灵草名> [数量]`**（已登记修仙帮助 misc_handler + README 指令表）。
- 版本 bump v3.3.1 → **v3.3.2**（metadata.yaml / README 版本行 / 新增 changelog 段）。

### 验证

## v3.3.4 - 装备属性「面板显示、战斗不生效」修复 + 插件加载崩溃修复

### 用户报告
「装备的属性在装备上之后数值似乎没有加到人物上去」。

### 诊断（/tmp/xx_test/diag_equip_chain.py 真实配置实测）
- 面板链（get_total_attributes）正常：青铜剑+玄铁甲贡献 物伤+10/法伤+5/物防+13。
- **战斗链（calculate_equipment_bonus）丢装备**：`{'atk': 15, 'defense': 0}`——玄铁甲 defense:10 完全没读到。
- **根因**：items.json 有 10 件旧格式 `equip_effects` 法器（4武器/4防具/2饰品，如青锋剑 attack:8、玄铁甲 defense:10、3005 attack:500、3008 defense:300）。面板 `parse_item_from_name` 有旧格式兼容（attack→物伤、defense→物防），战斗链只读新格式字段且武器只查 weapons.json ⇒ 旧格式防具战斗防御恒 0、旧格式武器（在 items 侧）战斗攻击恒 0。新手最先穿的就是这类中低档商店装。
- **配方产物核查**：forge_recipes 8 档产物全部存在于 weapons.json（新格式），打造链无幽灵装备。weapons/items 无同名冲突。

### 修复（v3.3.4）
1. **统一口径**：`models.py` 新增模块级 `resolve_equipment_attributes(config)`（新格式字段 + `equip_effects.attack→物伤`、`defense→物防` + 兼容顶层 atk 键）；`combat_manager.calculate_equipment_bonus` 与 `equipment_manager.parse_item_from_name` **共用此函数**，查找顺序统一（先 items 后 weapons）。
2. **面板/排行接入精炼**：`Player.get_total_attributes` 加可选 `refine_map`/`refine_per_star`（武器/防具攻防 ×(1+star×per_star)，精神力/心法不受影响，int(round) 逐项取整）；`/我的属性`、`/我的装备`、战力排行榜均传 `db.get_refine_map`。不传参行为与旧版一致（排行榜刻意不含临时丹药的设计不变）。
3. **⚠️ 致命副产物修复**：smoke_import 发现 v3.3.3 的 `ForgeHandlers`/`ForgeManager` **未登记进 `handlers/__init__.py` 与 `managers/__init__.py`**，而 main.py 顶层 `from .handlers import ForgeHandlers` ⇒ **v3.3.3 插件加载即崩**（此前所有 manager 级测试都走合成包绕过 __init__，故全绿也没抓到）。已补导出。

## v3.3.5 - 长文本回复自动转图片（IMAGE_MODE）

### 用户需求
「你能把返回文字做成返回图片吗，现在文字太多阅读起来很费劲」。

### 方案（零侵入全指令生效）
- **`main.py` 加 `on_decorating_result` 出站装饰钩子**（AstrBot 官方装饰机制，钩子内禁 yield，用 `event.get_result()` 改 chain）：单条纯文本回复 ≥ `IMAGE_MODE_MIN_LENGTH`（默认 300 字）→ `await self.text_to_image(text, return_url=False)` → `result.chain = [Image.fromFileSystem(path)]`。
- **模块级 helper `long_plain_text(chain, min_len)`**：全部组件 type 名均为 "Plain" 才取拼接文本（含 At/图片等富媒体不转），用 `type(comp).__name__` 判定保持零依赖可单测。
- **失败回退**：整个钩子 try/except，未配置 html-render/渲染异常/返回空 → 保留原纯文本，行为与旧版一致。
- **配置**：`_conf_schema.json` VALUES 加 `IMAGE_MODE`（bool 默认 true）、`IMAGE_MODE_MIN_LENGTH`（int 默认 300，非法值回退 300）。
- 修仙帮助尾加说明行；README 配置表加图片模式行 + changelog；metadata v3.3.5。

### ⚠️ 关键事实
- AstrBot 文转图官方 API：`self.text_to_image(text, return_url=False)`（Star 方法）+ `event.image_result(url)`；依赖宿主 html-render（Playwright）。`event.text_to_picture` **不存在**（文档只有 text_to_image/html_render）。
- 钩子判定用 type 名 → **测试 stub 组件类名必须叫 `Plain`/`Image`**（子类 _Plain 的 `__name__` 是 "_Plain" 会导致 helper 不识别，首轮测试 7 失败全是这个）。
- 帮助/排行等长面板天然被转图；战斗结算等短文本保持文字。
