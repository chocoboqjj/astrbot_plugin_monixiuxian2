## v3.3.2 - 突破丹背包校验修复 + 灵田一键种植

### Bug：突破丹无需拥有即可强行破境（且永不消耗）
**用户报告**：部分境界（元婴期明显，金丹期不明显）`/突破 <破境丹>` 即使背包没有丹药也会白嫖破境丹加成。

**根因（已确认通用，非分境界）**：
- `handlers/breakthrough_handler.py::handle_breakthrough` 指定丹名时，只校验 `pills_data` 存在 + `subtype=="breakthrough"` + `target_level_index` 匹配，**从不查 `player.get_pills_inventory()`，也从不扣丹**。
- `core/breakthrough_manager.py::execute_breakthrough` 直接把 `breakthrough_bonus` 算进成功率。
- 所谓「金丹期没事」实为当时背包恰好有结丹丹；检查缺失对所有境界生效（已用 9 项断言验证：无丹拒绝 / 有丹扣 1 枚 / 无丹名走基础率 / 修为不足不误扣）。

**修复（两层防御）**：
1. `breakthrough_handler.py`：指定丹名后先查背包，没有则拒绝并提示「可在丹阁购买，或用 /突破 以基础成功率突破」。
2. `breakthrough_manager.py`：突破条件（非最高境界 + 修为足够）满足后，才校验并**扣除**该破境丹；条件不足（如修为不够）不会误扣。死亡分支下玩家被级联删除，丹自然作废。

**⚠️ 设计决策**：破境丹现会**消耗**。原设计文档（sect_elixir_pills.md 2.3）只把破境丹描述为「一次性加成」未提消耗；本次按游戏经济与用户预期补上消耗，关闭「失败也无限白嫖」漏洞。若用户想保留「不消耗」旧行为，撤销这两处即可。

## v3.3.7 - 面板版式重设计 + 双主题（宣纸金默认 / 玄金备选）

### 用户需求（三轮反馈驱动）
1. 「太难看了，这不就是把文字弄个背景吗」⇒ 宣纸+金逐行翻译版被判负。
2. 「排版太难看了，重新做，文字描述不一定要沿用之前的」⇒ 允许重新设计信息架构与文案。

4. 「我觉得第一版的设计好」⇒ **回退到第一版宣纸+金配色**，但保留新版式。

### ⚠️ 关键坑：预览页「无样式」根因
`gen_preview_v336.py` 只把 `render_panel_html()` 的 `<body>…</body>` 内联到预览页，**把面板自带 `<style>`（`_CSS`）整块丢掉** ⇒ 浏览器按裸文字渲染，用户以为电脑坏了。
**教训**：预览渲染函数产物时，必须连 `<style>`/`<head>` 一起带上，或用 **iframe srcdoc** 独立渲染（本次采用后者，与宿主 `html_render` 截图环境一致，且 iframe 天然隔离 CSS，避免预览页 `.sub/.cap` 与面板 `.sub` 类名冲突；高度用 JS 读 `contentDocument.body.scrollHeight` 自适应，srcdoc 与父页同源可读）。

### 实现要点
- **版式重设计（不等同于逐行翻译）**：渲染器先识别面板类型（`_is_player/_is_equip/_is_help`）再从原始文本提取字段重排——
  - player = 游戏角色卡（道号主视觉 → 境界/灵根/职业徽章 → 战力巨字 → 修为/气血进度条 → 属性网格卡 → 随身装备 → 宗门脚注）
  - equip = 装备卡（武器/防具/心法大条目 + 功法胶囊 + 属性加成数值卡）
  - help = 指令手册（金色色块段落标题 + 指令斑马纹）
  - generic = 通用条目式
- **双主题**：`_CSS_THEME_PAPER` / `_CSS_THEME_GOLD` 两套 `:root` CSS 变量 + 共享 `_CSS` 结构 ⇒ **同一套 DOM/类名，仅配色不同**。`render_panel_html(text, theme)`、`THEMES` 字典、`DEFAULT_THEME="paper"`、未知主题回退默认（不抛异常）。配置项 `VALUES.PANEL_THEME`（string，default `paper`），`main.py` 读 `values.get("PANEL_THEME","paper")` 传入。
- **⚠️ 变量化重构的连带修改**：`_frame()` 加 theme 参数、四个 `_render_*(title, sections, theme)` 全部加形参、4 处 `_frame(...)` 调用点传 theme、入口 `render_panel_html` 分发传 theme —— **漏任一处 ⇒ 主题不生效或 TypeError**（模块级常量勿用 `self.`，同理勿漏形参传递）。

- 根因：`_SEP_RE = ^\s*[━═─]{4,}\s*$` **字符类漏了半角 `=`** ⇒ `====` 不匹配；且 help 布局的 raws 分支**没有分隔线处理**（generic 有、help 没有）。
- 修复：① `_SEP_RE` 加 `=`；② 抽 `_is_sep()` / `_div_html()` 公共函数；③ **help / generic / player-misc / equip-misc 四处统一**用 `_is_sep`→`_div_html()`；④ 补 `.p-div` CSS 规则（**此前 CSS 里根本没有 `.p-div` 定义**，generic 布局的装饰线也渲染不出来）。
- 效果：粗黑实线 → 金色菱形节点 + 渐隐横线（`s` 方块 rotate(45deg)）。
- 测试：`test_panel_renderer.py` 扩到 **48/0**（F2 段：━━━/════/────/==== 四种分隔线 → p-div 且原字符不残留、`.p-div` CSS 存在）。
