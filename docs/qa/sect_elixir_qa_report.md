## 3. 效果是否真的生效 —— 实测证据汇总

**已证实真生效（非仅返回成功文案）**：

| 承诺 | 实测 | 结论 |
|---|---|---|
| 聚气丹：闭关修炼速度 +10% | 闭关 60 分钟修为 **6000 → 6600**；倍率 1.10；持续 3600s；背包扣 1；落库 | ✅ 真生效 |

| 回元丹：灵气上限 +5%（灵修） | 50000 → **52500**（+2500） | ✅ 真生效 |
| 回元丹：气血上限 +5%（体修） | 40000 → **42000**（+2000） | ✅ 真生效 |
| 宗门凝神丹：精神力 +5% | 50000 → **52500**（+2500），DB 复核一致 | ✅ 真生效 |

（pill_manager.py:646）回退默认 100 → 该系上限仅 30 点。

> 与设计文档「已知限制-1」描述一致。但我判定其**应升格为 P2 缺陷**，理由是它是
> **玩家可见的文案承诺**（`SECT_ELIXIR_EFFECTS` + 丹药 `description` 均写「+5%」）与实际效果的严重不符。

## 4. 商店排雷结论

**结论：正常配置下排雷有效（PASS）；存在 1 处配置依赖型潜在泄漏面（P3）。**

- `shop_weight: 0` → 主商店 / 丹阁 / 百宝阁 **3 条路径 0 泄漏**（200 轮抽样 + 全量扫描）
- 负向对照证明断言有牙：`shop_weight: 100` 时丹阁命中 26 次、百宝阁 11 次、主商店 5/5 上架
- 购买路径安全：`handle_buy` 依赖 `_find_item_in_pavilions`（要求 `stock > 0`），不进阁即买不到
  （`find_item_by_name` 虽只校验 `price > 0` 能查到，但无库存，买不成）

**潜在泄漏面（BUG-5）**：`_weighted_random_choice`（shop_manager.py:121-122）在
`len(items) <= count` 时**直接返回全部候选、完全不看权重**。
当 `PAVILION_PILL_COUNT` 被配置为 ≥ 丹阁候选池（203）时，5 味丹药会全部上架。默认 10，暂不触发。

| ④ 新旧语义对比 | 改动前同场景会**直接写背包**发出「服用时提示配置不存在」的死物；改动后拒绝 + 提示 + 日志 | ✅ 改动后**严格优于**改动前 |

**判定依据**：`test_sect_building.py` 的旧 mock 用 `utility_pills_data={}`，这是**与生产真实形态不符的测试夹具**。
生产 `ConfigManager` 必然加载真实配置，不存在「丹药配置为空」的运行时状态。
因此 mock 同步载入真实配置 = **测试夹具对齐生产真实形态**，属**预期变化**。
即便真实发生配置损坏，改动后的表现（拒绝发放 + 明确提示 + 日志 + 可重领）也优于改动前（发死物）。

**结论：不是真实回归，同意工程侧处理。**

## 6. Bug 分级与复现步骤

### 🔴 P0：无

### 🟠 P2-1（Major）BUG-1：境界 0 弟子领到 3 味用不了的丹药

- **现象**：境界 0（炼气期一层，修为 < 500）弟子在 ≥2 阶丹房宗门领取后，
  回元丹 / 宗门凝神丹 / 宗门洗髓丹 **无法服用**，提示「境界不足！使用【X】需要达到【炼气期二层】」。
  每日领取会在背包持续堆积死物 —— **正是本次要根除的「领了却用不了」问题类的残留**。
- **复现步骤**：
  1. 新建角色（level_index=0，修为 0）
  2. `join_sect` 加入一个丹房 ≥2 阶的宗门（join_sect 无境界门槛）
  3. 执行「领取宗门丹药」→ 成功拿到 5 味
  4. 依次「服用丹药 回元丹 / 宗门凝神丹 / 宗门洗髓丹」
- **预期**：领到的每一味都能服用
- **实际**：3 味返回「境界不足」
- **根因**：`claim_sect_elixir`（sect_manager.py:705-720）只校验「丹药是否在配置中存在」，
  **未校验该弟子境界是否达到 `required_level_index`**；而 `use_pill`（pill_manager.py:160-169）有该校验。
- **建议修法（三选一）**：
  1. **推荐**：发放时按 `required_level_index` 过滤，跳过并提示「修为达 500（炼气期二层）后可领」；
  2. 把 3 味永久丹药门槛降到 0 —— **不可行**：境界 0 的突破增益全为 0 → 30% 上限额度为 0 →
     会被判「已达上限」仍然用不了（设计文档 §4.2 已论证）；
  3. 领取时对境界不足的丹药改为不发 + 提示。
- **级别理由**：仅影响境界 0 新弟子，升至境界 1（500 修为）后自愈 → P2 而非 P1。

### 🟠 P2-2（Major）BUG-2：回元丹「气血与灵气上限 +5%」跨系严重缩水

- **现象**：灵修吃回元丹，最大灵气 +2500 ✅，但最大气血 **40000 → 40030（+30）**，承诺 +2000，**缩水 98.5%**；
  体修反之，最大气血 +2000 ✅，最大灵气 **50000 → 50030（+30）**，承诺 +2500，**缩水 98.8%**。
  服用回执里会出现「⚠️ 受限提示：最大气血 部分受限(+30/2000)」，玩家可见。
- **复现步骤**：
  1. 灵修角色，境界 20，最大气血 40000
  2. 领取/给予「回元丹」→ 服用
  3. 观察最大气血
- **预期**：+5%（+2000）
- **实际**：+30
- **根因**：`config/level_config.json`（灵修）无 `breakthrough_blood_qi_gain`；
  `config/body_level_config.json`（体修）无 `breakthrough_spiritual_qi_gain` →
  `_get_base_attributes_for_level`（pill_manager.py:646）回退默认 100 → 每境界该系上限仅 30 点。
- **建议**：① 补齐两张境界表缺失字段（属全局数值调整，需策划 + 平衡评估）；② 或修正文案为「主系上限 +5%，跨系受限」。
- **级别理由**：玩家可见的文案承诺与实际效果严重不符。

### 🟡 P3（Minor）BUG-3：宗门洗髓丹「全部属性 +2%」不达标

- **现象**：
  - 灵修 8 项中 **6 项达标**，寿命 +15（承诺 +200）、最大气血 +30（承诺 +800）
  - 体修 8 项中 **5 项达标**，**法伤完全 +0**（承诺 +40）、寿命 +45（承诺 +200）、最大灵气 +30（承诺 +1000）
- **根因**：同 BUG-2 的境界表缺字段；另 `body_level_config[20].breakthrough_magic_damage_gain = 0`
  → 该系上限 = 0 → 体修法伤增益被完全阻断。
- **建议**：同 BUG-2；体修法伤 0 上限需单独确认是否为配置遗漏。

### 🟡 P3（Minor）BUG-4：低境界弟子服用增益形同虚设

- **现象**：境界 1 弟子 5 味均能返回「服用成功」，但实际增益极小 ——
  回元丹 最大灵气 +3 / 最大气血 +30；宗门凝神丹 精神力 +3；宗门洗髓丹 **仅寿命 +15**，其余全部「本境界增益额度已不足」。
- **建议**：文案补充「受当前境界属性上限约束」，或调整低境界额度基数。

### 🟡 P3（风险）BUG-5：weight=0 排雷依赖「抽样数 < 候选池」

- **现象**：`_weighted_random_choice`（shop_manager.py:121-122）在 `len(items) <= count` 时
  **直接返回全部候选、不看权重** → 5 味丹药全部泄漏进丹阁。
- **复现**：`shop.generate_pavilion_items(shop.get_pills_for_display, 210)`（≥ 候选池 203）
- **触发条件**：`PAVILION_PILL_COUNT` 被配置为 ≥ 203（默认 10，**当前不触发**）
- **建议（治本）**：在 `generate_pavilion_items` 入口先按 `data.shop_weight > 0` 过滤候选池，
  不依赖权重语义兜底。

### 🟡 P3（测试工程）BUG-6：`test_recycle_alchemy.py` 是 flaky 测试

- **现象**：25 次运行**失败 2 次（约 8%）**，结果在 15/16 与 16/16 之间跳变。
  设计文档 §7.2 记录的「16/16」**不可稳定复现**。
- **失败断言**：`产出 炼气丹×1 入丹药背包 pills={}`（炼丹失败分支 `💔 炼丹失败`）
- **根因**：`alchemy_manager.py:224` 用 `random.randint(1, 100)` 判定炼丹成功率，
  炼气丹配方 `success_rate: 85`，而**测试未固定随机种子**。
- **与本次改动无关**：`git diff --stat` 显示 `managers/alchemy_manager.py` **未被修改**，
  且炼丹链路不经过 `pill_manager` 的 `_use_permanent_pill` / `_resolve_percentage_gains`。
- **建议**：测试内 `random.seed(...)` 或 monkeypatch `random.randint`；**否则会持续污染 CI 信号**。
