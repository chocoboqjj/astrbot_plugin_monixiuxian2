## 🌟 特色功能

### 核心玩法
| 系统 | 说明 |
|------|------|
| **境界修炼** | 练气→筑基→金丹→元婴→化神→炼虚→合体→大乘→渡劫，九大境界逐步突破 |
| **战斗系统** | HP/MP/ATK/暴击/防御 真实计算，支持 PVP（切磋/决斗）和 PVE |
| **宗门系统** | 创建/加入宗门，职位管理，宗门建设与捐献 |
| **世界Boss** | 全服Boss降临，多人合力讨伐，按伤害排名瓜分奖励 |
| **秘境探索** | 挂机式秘境探索，7 档秘境，获取丰厚修为与灵石 |
| **历练系统** | 离线挂机获取收益，6 条路线从炼气到化神逐级解锁 |
| **炼丹系统** | 收集材料炼制丹药：修为丹 / **破境丹** / 临时增益丹 / 永久属性丹 |

| **传承系统** | 传承挑战争夺Buff加成，传承排行榜竞技 |

| **📖 新手引导** | `新手引导` 指令三步带入门，附 `修仙帮助` 完整指令清单 |

### 🏦 灵石银行
年利率5%，每日复利

| 指令 | 说明 |
|------|------|
| `银行` | 查看存款余额和待领利息 |
| `存灵石 <数量>` | 存入灵石，开始计息 |
| `取灵石 <数量>` | 取出存款 |
| `领取利息` | 每日可领一次利息 |
| `贷款 <数量>` | 普通贷款（0.5% 日利率，7 天期限） |
| `突破贷款 <数量>` | 短期贷款（0.8% 日利率，3 天期限） |
| `还款` | 偿还当前贷款（本金 + 利息） |
| `银行流水` | 查看最近 15 条交易记录 |

> ⚠️ **逾期后果**：贷款逾期未还会被银行追杀致死，所有修为与装备化为虚无。
>
> ⚠️ **身死不清债（v3.2.7）**：贷款尚未还清时身死（突破走火入魔 / 主动弃道重修 / 战斗死亡等），**未还清的债务会随你一同转世**——重开（「我要修仙」）后自动恢复为正常贷款，金额锁定为「本金 + 死亡时已产生的利息」并**固定免息**，另有 7 天宽限期，逾期仍会被追杀。
> - 唯一豁免情形：**逾期被银行追杀**（本就是因欠债而死，债务免除，避免「逾期 → 死 → 继承 → 再逾期」死循环）。
> - 债务最多继承 **3 次**，第 4 次死亡时强制免除，给玩家一条彻底出坑的路。
> - 恢复后的贷款仍受常规约束：不能借新贷、洞天产出继续被银行托管（防套利）、突破贷款自动还款照常生效。

### 🔥 炼丹系统
| 指令 | 说明 |
|------|------|
| `丹药配方` | 查看炼丹配方及成功率 |
| `炼丹 <配方ID>` | 炼制丹药（成功后存入丹药背包） |

> **四类配方**：
> - **修为丹**：聚气丹等，提升修为；
> - **破境丹**：筑基丹 / 结丹丹 / 凝婴丹 / 化神丹 / 炼虚丹 / 合体丹 / 大乘丹 / 渡劫丹，**受境界门槛限制**——只能炼制「目标境界 ≤ 自身当前境界 + 1」的破境丹（筑基后期最高可炼结丹丹），破境丹泛滥由稀有材料（灵兽内丹 / 星辰石 / 天材地宝 / 紫金沙 / 混沌精华）限量；
> - **临时增益丹**：疾风丹、狂暴丹等限时增益；
> - **永久属性丹**：小力量丹 / 通灵丹 / 霸体丹 / 天灵丹等永久提升属性（受每境界 30% 增益上限约束）。

### ⚒️ 炼器系统（装备打造 + 精炼升星）
| 指令 | 说明 |
|------|------|
| `炼器配方` | 查看可打造的装备及所需材料、成功率 |
| `炼器 <配方ID>` | 打造装备（消耗灵石+材料，成功后存入储物戒） |
| `精炼 <装备名>` | 消耗精铁 / 紫金沙 + 灵石提升装备星数（每星 +10% 攻防） |

> **武器与防具均可打造**，共 9 档品级（凡品 → 灵品 → 地品 → 天品 → 皇品 → 圣品 → 帝品 → 道品 → 仙品 → 混元先天），
> 境界门槛与品级严格对应：炼气可炼凡品、筑基可炼灵品、金丹可炼地品/天品、元婴可炼皇品……合 体可炼道品、大乘可炼仙品、渡劫可炼混元先天。
> 高阶配方消耗紫金沙 / 混沌精华 / 神兽之骨 / 仙器碎片等稀有材料（这些材料来自**高阶秘境与高阶历练**）。
> 精炼升星的攻防加成**真实作用于**决斗、Boss、灵眼争夺、传承挑战等所有战斗。
> 打造与精炼是孤儿材料（精铁、星辰石、灵兽内丹、天材地宝、**紫金沙** 等）的核心消耗出口。

### 📜 功法合成
| 指令 | 说明 |
|------|------|
| `功法合成` | 查看残页合成配方（各档所需残页数、保底品级、灵石消耗） |

> 具体功法在对应品级池中随机。

### ☠️ 投毒
| 指令 | 说明 |
|------|------|

> - **得手**：目标获得 `中毒` 负面状态（属性倍率下调）；
> - **被识破**：扣除灵石罚款 + 30 分钟投毒冷却。
> 投毒只影响属性，**不会直接杀人**。

> ⚠️ **贷款存续期间洞天产出被银行托管**：可以正常购买/升级洞天，但**还清贷款前无法收取产出**（还清后立即恢复）。这是为了杜绝「贷款 → 买洞天 → 用洞天收益还贷」的套利闭环。

> ℹ️ v3.2.7 起，**转世继承回来的贷款同样触发托管**（恢复后即为普通贷款），不会出现「死后转世绕过托管」的缺口。

| `VALUES` 面板主题（v3.3.7 新增） | `PANEL_THEME` | 转图面板的视觉主题；`paper` = 宣纸金（默认，第一版设计）、`gold` = 玄金暗色。未知值回退默认主题 |

## 📝 更新日志

### v3.3.8 - 道具回收/服用/赠送修复 + 炼丹炼器体系扩充 + 功法合成与投毒 + 高阶秘境历练

**🐛 修复：部分道具无法回收**

- **根因**：`config/items.json` 是所有物品的**唯一权威登记处**，掉落表引用的物品必须在此登记，否则成为「幽灵物品」——可掉落、可拾取，但回收时查不到配置就静默失败。
  扫描全部掉落表后发现 **4 个 Boss 材料从未登记**：混沌精华、神兽之骨、远古秘籍、仙器碎片。
- **修复**：补录进 `config/items.json`（id 2023~2026，含品级/价格/权重/描述）。
- **永久守护**：`smoke_import.py` 新增「幽灵物品守护」——所有掉落表（config JSON + manager 源码正则扫描）里的物品名必须能在物品表中找到，否则冒烟测试直接失败。

**🐛 修复：无法一次回收多个相同物品**

- **根因**：宿主 `CommandFilter` 的 `str` 类型参数**只取消息里的第一个 token**，`/回收 灵草 5` 传到 handler 的实参是 `"灵草"`，数量在到达 handler 之前就丢了。
- **修复**：新增 `handlers/utils.py::parse_counted_args()`，从 `event.get_message_str()` **原始消息**重新解析「名称 + 数量」，支持 `灵草 5` 与 `灵草x5` 两种写法。回收、服用、赠送三条链路统一复用。

**🐛 修复：无法服用三品凝神增益丹等 33 味丹药**

- **根因**：`items.json` 里的 33 味「旧系统丹药」（含三品凝神增益丹）只登记在该表中，而 `PillManager.get_pill_by_name` **只查 pills / exp_pills / utility_pills 三张新表** ⇒ 一律报「配置不存在」。
- **修复**：`get_pill_by_name` 兜底查 `items_data`；新增 `apply_legacy_pill_effects()` 统一旧格式 `effect` 字典的语义（add_hp / add_experience / add_max_hp / add_spiritual_power / add_mental_power / add_attack / add_defense / add_gold / add_breakthrough_bonus），百宝阁购买与丹药背包服用共用同一套实现。

**🐛 修复：无法赠送丹药**

- **根因**：赠予链路只查**储物戒**，而丹药在**丹药背包**（`pills_inventory`），且储物戒明确拒绝存丹药 ⇒ 赠丹必然报「储物戒中没有【X】」。
- **修复**：`handlers/storage_ring_handler.py` 新增 `_is_pill` / `_take_for_gift` / `_give_to_player`，赠出、接收、拒绝返还三条链路全部按丹药/普通物品分流。

**✨ 优化 1：一次服用多枚相同丹药**

- `/服用丹药 <丹药名> [数量]` 支持批量；**永久属性丹受「每境界 30% 增益上限」约束**，多枚时逐枚结算，额度耗尽的那几枚**不会被白白消耗**（已生效枚数照常结算并提示剩余）。

### v3.2.9 - 天灾人祸系统（每小时随机天灾，只夺资源不夺命）

**🟡 新增：世界会随机找一位道友的麻烦**

- **需求**：每隔一小时触发一次随机「天灾人祸」，随机惩罚一名玩家，扣除其灵石与修为；**惩罚数量最少可以是 0**（无事发生）。
- **设计定案**（与用户逐项确认）：
  1. **惩罚力度** → 按**资产比例**扣（灵石 8%~18%、修为 4%~12%，随天灾种类不同，另带 ±20% 抖动）。按当前资产比例计算天然适配不同境界的玩家——新玩家不会被一击打爆，大佬才会真正感到痛。
  2. **选人方式** → **全体玩家等概率**抽取，不按财富加权，避免富者恒被盯上。
  3. **致死性** → **绝不致死**。只做 `gold` / `experience` 的定向扣减，**不触碰** `state` / `lifespan`，**不删号**，也**不走** `PenaltyManager.punish()`——与已有的走火入魔 / 银行追杀明确区分。

- **天灾种类**：10 种（6 天灾 + 4 人祸），按权重随机抽取，各有独立的灵石/修为扣减比例与描述文案——九天雷劫、地脉崩裂、瘟疫横行、业火焚身、天河倒灌、妖兽下山、劫修夺宝、同道觊觎、宗门逼债、谣言四起。

- **定魂丹护盾接入**（`has_debuff_shield`）：该字段此前是「只设不消」的悬空特性（全库无消费点），本系统作为它的**首个消费点**——有护盾时**完全免疫**本次天灾，挡下后按配置消耗。

### v3.2.8 - 世界 Boss 不可无限挑战（次数 + 冷却 + 安慰奖封顶）

**🔴 P0：世界 Boss 无任何挑战限制 ⇒ 可无限连发刷奖、磨血抢人头**

- 现象：`challenge_boss` 此前**完全没有次数或冷却限制**——每次挑战前 `player.hp = player_stats.hp` 会把气血重算为满值，失败还按「造成伤害比例」发放**无封顶**的安慰奖。于是玩家可以：
  1. **无限刷安慰奖**——每次失败都按伤害比例拿到灵石，无上限、无冷却；
  2. **磨血抢人头**——反复挑战把 Boss 血量压到濒死，让后来的玩家轻松收割（先手者独占收益）；
  3. **无视战力反复送死**——没有成本约束，低境界玩家可以毫无代价地连点。
  - 对比：灵眼争夺有 5 分钟冷却、决斗有冷却，**唯独世界 Boss 裸奔**。
- **修复（三重闸门）**：
  1. **次数上限**——每只 Boss 每位道友默认只能出手 **1 次**（`max_challenges`）；次数按 Boss 实例（`boss_id`）计数，**Boss 刷新后自动重置**，无需额外的每日重置任务。
  2. **挑战冷却**——两次挑战之间需间隔 **10 分钟**（`challenge_cooldown`），提示剩余时分秒。
  3. **安慰奖封顶**——失败奖励按「造成伤害占 Boss 初始血量」计算，但**封顶为完整奖励的 50%**（失败最多算半个成功）。原因：次数上限只限制了单玩家刷奖，而「每个玩家都拿一份完整安慰奖」在人多服务器仍会造成灵石通胀（人数 × 完整奖励）。
- **并发安全**：挑战机会通过 `reserve_boss_challenge` 以**单条 SQL**（`INSERT ... ON CONFLICT DO UPDATE ... WHERE challenge_count < ?`）完成「检查次数 + 递增」，靠 `cursor.rowcount` 判定成败 ⇒ **同一玩家的并发请求最多只有一条能占位成功**，杜绝双挑战重复领奖。战斗异常时自动回滚已占位的次数，不让玩家白白损失机会。
- **顺带修复（并发双领奖）**：`defeat_boss` 此前是**无条件** `UPDATE boss SET status = 0`，两名玩家同时挑战时会各自基于同一份旧血量「算出胜利」，双双领走完整奖励并双发击杀广播。现改为**条件 UPDATE**（`WHERE boss_id = ? AND status = 1`）并靠 `rowcount` 判定 ⇒ 只有**首个真正完成击杀**的玩家拿完整奖励并发广播；其余视为「打在尸体上」，按封顶后的安慰奖结算。
- **玩家可见**：`/世界Boss` 面板追加该玩家的挑战额度（`🎯 你的挑战次数：0/1（剩余 1 次）`）与冷却剩余（`⏳ 挑战冷却：还需 9 分 12 秒`），让限制可预期、可规划。Boss 降临的群广播也会前置告知「限挑战 N 次 / 需休整 N 分钟」。
- **数据库**：新增 **v24 迁移**（`data/migration.py`，`LATEST_DB_VERSION` 23→24）——新建 `boss_challenges` 表（`boss_id` + `user_id` 唯一），记录「玩家 × Boss」的挑战次数与上次挑战时间；全新安装路径 `_create_all_tables_v2()` 同步建表。新 Boss 生成时自动清理历史 Boss 的挑战记录（数据瘦身）。
- **配置**：`config/boss_config.json` 与默认配置新增 `max_challenges`（默认 1，设为 0 即不限次数）与 `challenge_cooldown`（默认 600 秒，设为 0 即不限制）。
- **说明**：Boss 战**保留满血入场**（未改为消耗气血）——本插件的气血并非核心资源模型（任何一次决斗 / 切磋都会重算满血），改成扣气血会引入「血量卡死、无法再战」的新问题；防无限挑战改由上述三重闸门承担。
- **验证**：新增世界 Boss 挑战限制专项回归测试（v24 迁移结构/幂等、次数上限、冷却拦截、Boss 刷新重置、并发原子占位、安慰奖封顶、战斗异常回滚、面板额度显示、不限次数配置、并发击杀唯一性）——**50/50 通过**；另新增端到端测试（存量库 v22→v24 升级、全新安装、占位/释放/清理全链路）——**17/17 通过**。既有回归 231 项全绿。

### v3.2.7 - 贷款死亡后债务追溯（身死不清债）

**🔴 P0：借钱 → 死亡 → 重开白嫖（债务凭空消失）**

- 现象：玩家贷款后身死（突破走火入魔 / 主动弃道重修 / 战斗死亡等），`delete_player_cascade` 会把未还清的 `active` 贷款直接置为 `bad_debt`（免除）。玩家重开（「我要修仙」）后债务静默消失 ⇒ **借 100 万 → 死亡 → 重开白嫖**，贷款系统形同虚设。
- **修复（债务继承制）**：
  1. **死亡时债务不免除，转入「继承待偿」**（`managers/bank_manager.py::inherit_debt_on_death`）——死亡瞬间锁定应还总额 = **本金 + 死亡时已产生的利息**，之后**固定免息**不再增长；贷款状态由 `active` → `carried`。
  2. **重开时恢复为正常贷款**（`handlers/player_handler.py::handle_start_xiuxian` → `restore_inherited_debt`）——恢复后：本金 = 锁定的应还总额、**利率归零（固定免息）**、到期时间 = 重开时间 + 宽限期（默认 7 天），并重建被级联删除的银行账户。恢复后的贷款**能被所有既有系统看到**（`get_active_loan`）：不能借新贷、洞天产出继续被托管（v3.2.5 防套利不被绕过）、突破贷款自动还款照常生效。
  3. **按死因分流**（`core/penalty_manager.py::PenaltyReason.inherits_debt`）——**仅「逾期被银行追杀」（BANK_KILL）免除债务**（玩家本就因欠债而死，若继续继承会形成「逾期 → 死 → 继承 → 再逾期 → 再死」死循环）；其余死因（走火入魔 / 战斗死亡 / 主动重修）一律追溯。
  4. **继承次数上限**——最多继承 **3 次**（默认），第 4 次死亡时债务强制豁免，给玩家一条彻底出坑的路。
  5. **主路径与兜底路径语义统一**——债务处理提取为模块级函数 `apply_death_debt(db, user_id, reason)`，4 处兜底直调 `delete_player_cascade` 的路径（突破死亡 / 银行逾期 / 弃道重修 / 定时逾期检查）全部接入，避免「主路径继承、兜底路径免除」的不一致。
- **顺带修复（重要既有 Bug）**：`bank_loans` 表的 `UNIQUE(user_id, status)` 约束导致同一用户**每种状态只能有一行** ⇒ 玩家**一生只能成功还清一次贷款**（第二次 `active → closed` 抛 `IntegrityError`，贷款卡在 active 永不结算）。v23 迁移重建该表，改为两条**部分唯一索引**（`status='active'` / `status='carried'` 各一条），允许保留多条 `closed` / `bad_debt` / `overdue` 历史行。
- **数据库**：新增 **v23 迁移**（`data/migration.py`，`LATEST_DB_VERSION` 22→23）——`bank_loans` 增 `inherit_count` / `settled_amount` / `inherit_at` / `grace_until` 四列、去除表级 UNIQUE、重建两条部分唯一索引；迁移含去重步骤（保留每个用户最新一条 `active`/`carried`，避免极端脏数据导致索引创建失败）。全新安装路径 `_create_all_tables_v2()` 同步更新。
- **配置**：新增 `BANK` 配置段（利率 / 额度 / 期限此前全部走代码默认值），其中 `DEBT_INHERIT_MAX`（继承次数上限，默认 3）与 `DEBT_INHERIT_GRACE_DAYS`（宽限期天数，默认 7）可调；`DEBT_INHERIT_MAX` 设为 0 即完全退回「死亡即清债」的旧行为。
- **验证**：新增贷款债务专项回归测试（v23 迁移结构/幂等/去重、死亡分流、继承金额锁定、重开恢复、恢复后可见性、3 次上限豁免、还款后可再次贷款、兜底路径一致性）——**44/44 通过**。

### v3.2.6 - 天地灵眼时效化 + @人 PVP 争夺

### v3.2.4 - 修复 `@玩家` 类指令在 QQ 官方机器人下全部失效

**🔴 P0：双修 / 切磋 / 决斗 / 赠予 / 宗门管理 / 传承挑战的 `@玩家` 全部失效**

- 现象：`/双修 @对方`、`/切磋 @对方` 等在 QQ 官方机器人下提示「对方还未踏入修仙之路」「请指定切磋目标」「请指定赠予对象」。
- **根因（框架侧，已核对 AstrBot master 源码）**：`qq_official` 适配器的 `_parse_from_qqofficial()` 在入站消息链里**只会放一个代表"机器人自己"的 At 组件**——
  - 群@机器人消息（`GROUP_AT_MESSAGE_CREATE`）：QQ 官方的 `mentions` 数组**不含机器人自身**，适配器取不到 bot id，于是放入 `At(qq="qq_official")`，一个**字面量占位符**；
  - C2C 私聊：同样是 `At(qq="qq_official")`；
  - 仅群全量消息模式且确实 @了机器人时，才是 `At(qq=机器人openid)`。

  而被 @ 的**其他用户**根本不进消息链，只以 `<@!member_openid>` / `<qqbot-at-user id="..."/>` 文本标记留在纯文本里（腾讯官方 openclaw-qqbot 的 `stripMentionText` 证实该 markup 用的就是 `member_openid`，与 `get_sender_id()` 同源，可直接作玩家库主键）。
- **触发条件**：v3.1.4 的 `extract_target_id()` 优先级为「① 消息链 At → ② 指令参数 → ③ CQ 码/数字兜底」：
  - ① 命中的永远是**机器人自己**（或 `"qq_official"` 占位符）→ 拿机器人 ID 查玩家库 → 查无此人；
  - ② 命中的是**未解析的标记文本** `<@!xxx>` → 同样查无此人；
  - ③ 只服务 OneBot。
  - 六个入口（双修 / 切磋 / 决斗 / 传承挑战 / 宗门踢人·传位·职位 / 赠予）共用该函数，故集体失效。赠予更严重：它自己那份重复的 At 解析还要求 `isdigit()`，openid 直接判死。

**改动**
- 重写 `handlers/utils.py::extract_target_id()` 为 5 级优先级，并新增 `strip_at_markup()` / `strip_target_from_text()` / `looks_like_user_id()` 三个 helper。
- `storage_ring_handler.handle_gift_item()` 删除自己那份重复且同样失效的 At 解析，改走统一函数 + 文本清洗（避免 `<@!xxx>` 污染物品名解析）。

**新的提取优先级**
| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 消息链 At 组件 | OneBot 可靠；QQ 官方下先按 `get_self_id()`/`get_sender_id()` 与占位符表剔除"机器人自己"再取 |
| 2 | 指令参数 / 消息纯文本中的 @ 标记 | QQ 官方主路径：`<@!member_openid>`、`<qqbot-at-user id="..."/>`；同时覆盖 OneBot 的 `@昵称(QQ号)` 与残留 CQ 码 |
| 3 | 原始 payload 的 `mentions` 列表 | QQ 官方兜底（平台未把标记留在 content 时），取第一个非机器人 @，优先 `member_openid` |
| 4 | 指令参数作为裸 ID | 兼容 openid 等非数字 ID；仍含 `<>[]()` 的未解析标记一律拒绝 |
| 5 | 纯文本中的独立数字 token | OneBot 历史兜底；改为整词匹配，避免把 openid 里的 5 连数字截出来当 ID |

**🧪 验证**
- 新增回归测试 34/34 通过：QQ 官方 4 种消息形态（群@占位 At / 新标记 / 全量模式@机器人 / 唤醒词无 At）+ C2C 手填 openid + `mentions` 结构化兜底 + `@全体成员`不当目标 + 含 5 连数字的 openid 不被截断 + OneBot 4 种形态（含 `@机器人 @目标` 双 At）+ 赠予端到端 4 例（QQ 官方@ / OneBot@ / 未指定 / C2C 手填）。
- 全量导入冒烟通过：`handlers` 全模块 + `main.py` 90+ 指令注册无 import 错误。
